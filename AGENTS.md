# dev-test-api — Agent instructions

Fullstack monorepo: **Go + Gin** REST API + **Vue 3 + Vite + Vuetify** web SPA + **React Native + Expo** mobile app + **shared TS** package.

## Commands

### Backend (root)

| Command | Action |
|---------|--------|
| `make install` | `go mod tidy` — sync Go dependencies |
| `make dev` | Start Go server with live reload (`go tool air`) |
| `make build` | Build Go binary to `./tmp/main` |
| `make run` | `go run main.go` on `:8080` |
| `make swagger` | Regenerate `docs/` from Swagger annotations |
| `make check` | `make fmt` then `make vet` |
| `make test` | Unit tests (`go test -short -count=1`) |
| `make test-cover` | Tests with coverage (`-coverprofile`) |
| `make setup` | Install lefthook git hooks (run once after clone) |
| `make clean` | Remove `tmp/` and `docs/` |

Always run `make fmt` after any backend change to format Go code, then `make vet` to catch static issues. `make check` does both.

### Web (`apps/web/`)

| Command | Action |
|---------|--------|
| `make fe-install` | `pnpm install` (workspace root) |
| `make fe-dev` | Vite dev server on `:3000` (proxies `/api` → `:8080`) |
| `make fe-build` | Production build (`vue-tsc` + `vite build`) |
| `make fe-lint` | ESLint (`--fix`) |
| `make fe-check` | TypeScript check (`vue-tsc --build`) |

### Mobile (`apps/mobile/`)

| Command | Action |
|---------|--------|
| `pnpm --filter mobile start` | Start Expo dev server |
| `pnpm --filter mobile typecheck` | `tsc --noEmit` |
| `pnpm --filter mobile android` | Start on Android |
| `pnpm --filter mobile ios` | Start on iOS |

### Shared package (`packages/shared/`)

| Command | Action |
|---------|--------|
| `pnpm --filter @devtest/shared typecheck` | Type-check shared TS |

### Workspace-level

| Command | Action |
|---------|--------|
| `pnpm typecheck` | Type-check all packages (shared + web + mobile) |
| `pnpm lint` | Lint all packages |
| `pnpm web` | Start web dev server |
| `pnpm mobile` | Start Expo dev server |

Always run `make fe-check` and `make fe-lint` after any web change. `make fe-build` is only required in CI and before deploy — it's too slow for the dev loop (~8s) and adds no signal that type-check + lint don't already catch.

## Key facts

- **NEVER create commits** — commits are manual. Only stage, diff, suggest.
- **Secrets** — never hardcode keys, passwords, or tokens. Use `.env` for Go, `VITE_*` env vars for web. Never commit `.env`.
- **`internal/` is Go-private** — the compiler blocks external imports.
- **`docs/` and `tmp/` are auto-generated and gitignored** — never edit them manually.
- **Air** and **Lefthook** are Go project tools in `go.mod` — invoke via `go tool air`, `go tool lefthook`, or their `make` targets.
- **Pre-commit hooks** (lefthook): `gofmt -l` check + `go vet ./...` + `go test -short` (unit, no DB). Run `make setup` after clone.
- **CI** (`.github/workflows/backend.yml` + `frontend.yml`): `gofmt -l`, `go vet ./...`, `go build ./...`, `go test -short ./...` on push/PR to `main`.
- **Swagger UI** at `/swagger/index.html` when server is running.
- **Swagger spec** — the canonical API reference is `docs/swagger.yaml`. When web/mobile types need to match backend endpoints, request/response shapes, or query parameters, read this file first. The JSON equivalent (`docs/swagger.json`) is also valid. Both are auto-generated by `make swagger` — never edit them manually.
- **Backend ↔ Shared ↔ Apps sync** — the backend is the source of truth for API contracts. Types flow: `docs/swagger.yaml` → `packages/shared/src/types/` → re-exported by `apps/web/src/types/` (thin re-exports) and imported by mobile via `@devtest/shared`. Key mappings:
  - `internal/models/*.go` fields → `packages/shared/src/types/*.types.ts` interfaces
  - `internal/modules/*/response.go` shapes → `packages/shared/src/types/*.types.ts`
  - New/removed endpoints → update `packages/shared/src/types/` + re-exports in `apps/web/src/types/` + `apps/web/src/api/services/`
  - If unsure about endpoint shapes, read `docs/swagger.yaml`
  - **Naming convention**: both sides use camelCase for JSON keys. Go struct tags (`json:"camelCase")` and TypeScript interfaces use the same casing — no conversion needed.
- **Envelope / RFC 9457 / error language** — the canonical contract is in `.agents/backend/resues.md`. The web and mobile clients implement the consuming side; shared defines the TypeScript mirror (`ApiError`, `PaginatedResponse`).
- **Context7 MCP** — available for Gin, GORM, jwt, swag docs. Always `resolve-library-id` first, then `query-docs`.
- **Vuetify MCP** — available via `opencode.json`. Query component APIs with `vuetify_get_component_api_by_version` or `vuetify_get_feature_guide`.
- **Bash defensive patterns** — skill `bash-defensive-patterns` (`wshobson/agents`) ya instalada (ver `skills-lock.json:9`). Todo script `*.sh` / hook `lefthook.yml` / `scripts/` debe seguirla: `#!/usr/bin/env bash` + `set -Eeuo pipefail`, `trap ERR/EXIT`, `command -v` dependency checks, variables siempre `"$quoted"`, `[[ ]]`, `mapfile/readarray`, `mktemp -d` con `trap EXIT`, y `atomic_write` para escrituras. Referencia: `.agents/skills/bash-defensive-patterns/SKILL.md` (gitignored, fuente es `skills-lock.json`).
- **Log icons** — prefix Go `log.*` calls with emoji (❌ errors, ✅ success, 🚀 startup, 🛢️ database, 🌱 seed). Pick the most descriptive icon per context.
- **Tests** — backend: `testing` + `testify` unit tests (mocked `Store`). `make test` (unit, no DB), `make test-cover`. Lefthook pre-commit runs `go test -short`.

## Domain rules

Backend, web, mobile, and shared have separate rule files with detailed conventions:

### Backend: `.agents/backend/`

| File | Purpose |
|------|---------|
| `architecture.md` | Module anatomy (request → response → mapper → store → service → handler → routes), wiring, GORM, Swagger |
| `responses.md` | **SOURCE OF TRUTH**: envelope format, RFC 9457 errors, error language (title: EN, detail: ES), camelCase, DTO conventions, JWT context |
| `dependencies.md` | Safety checks before `go get` — security, maintenance, licensing |

### Web: `.agents/web/`

| File | Purpose |
|------|---------|
| `architecture.md` | Directory ownership, data flow (api → queries → features), feature structure, wiring checklist, shared re-export pattern |
| `api-client.md` | Axios interceptors (references `responses.md` for contract), envelope unwrap, service patterns, `useFormErrors` |
| `patterns.md` | TanStack Query patterns, debounce 500ms, Vue/TS conventions, Pinia stores, pagination, v-slot bracket syntax |
| `dependencies.md` | Safety checks before `pnpm add` — security, maintenance, licensing |

### Mobile: `.agents/mobile/`

| File | Purpose |
|------|---------|
| `architecture.md` | Expo/RN structure, metro monorepo, shared usage, SecureStore token storage, HTTP client |
| `dependencies.md` | Safety checks before `pnpm add` — Expo compatibility, native module checks |

### Shared: `.agents/shared/`

| File | Purpose |
|------|---------|
| `architecture.md` | What goes in shared vs app, barrel exports, re-export pattern in web, CodeChallenge dedup, sync flow (swagger → shared → apps) |
